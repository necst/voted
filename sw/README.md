## SW – Host Application (XRT)

Purpose
-------
This directory contains the host-side application used to control and execute
the VOTED accelerator.

The host code is written in C++ and uses the XRT Native API to load the xclbin,
manage buffers, and launch kernels on the target device.

The same host code is intended to work across:
- Versal systems
- Alveo accelerator cards
- HBM-based devices
with minimal or no modifications.

Requirements
------------
- XRT installed and available (XILINX_XRT set)
- Vitis / HLS headers available (XILINX_HLS set)
- C++ compiler with C++17 support
- GNU Make
- Xilinx environment correctly initialized

Build Configuration
-------------------
The Makefile uses the following settings:

- C++ standard: C++17
- XRT Native API (xrt_coreutil)
- Include paths from XILINX_XRT and XILINX_HLS

The generated executable is:
host_overlay.exe

1) Build Host Application
------------------------------------------------------------

Command
-------

```bash------------------------------------------------------------
2) Hardware Emulation Setup (hw_emu)
------------------------------------------------------------

Overview
--------
When running hardware emulation, you must enable the emulation environment
before executing the host application.

Command
-------
source ./setup_emu.sh -s on

Notes
-----
- Run this from inside the sw/ directory.
- This step is required only for hardware emulation (hw_emu).
- Make sure the linking step has produced overlay_hw_emu.xclbin.
make all
```

or equivalently:

```bash
make build_sw
```

This command:
- compiles host_code.cpp
- links against the XRT libraries
- generates the executable host_overlay.exe

After compilation, the Makefile automatically:
- removes any existing local xclbin files
- creates symbolic links to:
  ../linking/overlay_hw.xclbin
  ../linking/overlay_hw_emu.xclbin

This ensures the host application always uses the latest xclbin
generated by the linking stage.

------------------------------------------------------------
2) Hardware Emulation Setup (hw_emu)
------------------------------------------------------------

Overview
--------
When running hardware emulation, you must enable the emulation environment
before executing the host application.

Command
-------

```bash
source ./setup_emu.sh -s on
```

Notes
-----
- Run this from inside the sw/ directory.
- This step is required only for hardware emulation (hw_emu).
- Make sure the linking step has produced overlay_hw_emu.xclbin.

------------------------------------------------------------
2) Run Host Application
------------------------------------------------------------

Command
-------

```bash
make run_sw
```

or directly:

```bash
./host_overlay.exe
```

The executable loads the xclbin and launches the accelerator
using the XRT Native API.

------------------------------------------------------------
3) Cleaning Generated Files
------------------------------------------------------------

Command
-------

```bash
make clean
```

This removes:
- the host executable
- XRT and Vivado runtime artifacts
- logs, journals, and temporary files
- any locally generated or linked xclbin files

------------------------------------------------------------
Notes and Best Practices
------------------------------------------------------------
- Ensure the xclbin has been generated in the linking directory before running
  the host application.
- Use the hw_emu xclbin when running hardware emulation.
- When switching between hw and hw_emu, rebuild or relink to ensure the correct
  xclbin is used.
- Environment variables XILINX_XRT and XILINX_HLS must be correctly set.
